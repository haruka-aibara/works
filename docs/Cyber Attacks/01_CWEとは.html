CWE — 脆弱性の「種類」に付く番号

脆弱性の報告には番号が2種類出てくる。片方は個体を、もう片方は原因を指している。

CVE と CWE、どちらも番号なのに何が違うのか

脆弱性の情報を読むと CVE-2024-12345 と CWE-89 が並んで書かれている。どちらも「脆弱性の番号」に見えるが、指しているものが違う。

CVE は「どの製品の、どの脆弱性か」という個体の識別子。1件見つかるたびに新しい番号が振られる。対して CWE（Common Weakness Enumeration）は「なぜ起きたか」という弱点の種類の識別子で、SQL インジェクションなら CWE-89、クロスサイトスクリプティングなら CWE-79 と決まっている。製品が違っても原因が同じなら、CWE は同じ番号になる。

どう使い分けるか

運用側は CVE で動く。「この製品のこのバージョンが該当するか、パッチはあるか」を判断する単位が CVE だからだ。

開発側に再発防止を伝えるときは CWE で話す。「CVE-2024-12345 を直してください」だと修正が1件で終わるが、「CWE-89 が出ている」と言えば、同じ書き方をしている他の箇所やコーディング規約・レビュー観点まで話が広がる。

よく出る弱点をまとめた CWE Top 25 は毎年更新されている。自分たちのレビュー項目を1から考えるより、ここから関係する項目を抜き出すほうが早い。
