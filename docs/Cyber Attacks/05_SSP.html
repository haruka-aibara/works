SSP（スタックカナリア）— 戻る直前に見張り値を確かめる

リターンアドレスが書き換えられたことを、関数から戻る前に検知する仕組み。

リターンアドレスの書き換えをどう気づくか

C 言語などでは、確保した領域より大きなデータを書き込むと、はみ出した分が隣の領域を上書きしてしまう（バッファオーバーフロー）。スタック上では、変数のすぐ先に「関数を抜けたあとどこへ戻るか」を示すリターンアドレスが置かれている。ここを攻撃者の用意した番地に書き換えられると、プログラムの流れを乗っ取られる。

書き換え自体を止めるのは難しい。そこで SSP（Stack Smashing Protector）は発想を変える。リターンアドレスの手前に見張り用の値を置いておき、関数を抜ける直前にそれが変わっていないか確かめる。あふれてリターンアドレスまで届いたなら、途中にある見張り値も必ず壊れているはずだからだ。炭鉱のカナリアになぞらえて「カナリア」と呼ぶ。

有効にするには

GCC / Clang のコンパイルオプションで入る。-fstack-protector は保護対象の関数が限られるため、実務では-fstack-protector-strong が使われることが多い（配列やアドレス参照を持つ関数まで広げる）。-fstack-protector-all はすべての関数に入れるが、そのぶん遅くなる。

カナリアで防げるのは「連続してあふれてリターンアドレスに届く」型だけ。関数ポインタを直接書き換える、離れた場所を狙って書き込む、領域外を読み取るといった攻撃はすり抜ける。有効になっているから安心、とは考えないほうがいい。
