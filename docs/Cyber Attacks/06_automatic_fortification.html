automatic fortification — ソースを直さずに境界チェックを入れる

あふれてから気づくのではなく、コピーする時点で止める。コンパイルオプションだけで入る保護。

危ない関数を全部書き換えるのは現実的でない

strcpy や sprintf はコピー先のサイズを受け取らないので、入力が長ければ黙ってあふれる。安全な関数に置き換えればいいのだが、既存のコードすべてを直すのは手間もリスクも大きい。

そこで glibc と GCC には、コンパイル時にコピー先のサイズが分かる場合だけ、自動的に境界チェック付きの関数へ差し替える仕組みがある。ソースを1行も書き換えずに保護が入るので automatic fortification（自動要塞化）と呼ばれ、-D_FORTIFY_SOURCE=2 のようにマクロを定義して有効にする。

使うときに知っておくこと

  • 最適化を有効にしないと効かない。-O1 以上と一緒に指定する必要がある（サイズの判定にコンパイラの解析結果を使うため）。
  • レベルがある。=1 は動作を変えない範囲の検査、=2 はより厳しく、規格違反の使い方も落とす。ディストリビューションの標準ビルドでは =2 以上が既定になっていることが多い。
  • 検知したときの動作は「異常終了」。攻撃は防げるが、そこで落ちること自体は避けられない。
