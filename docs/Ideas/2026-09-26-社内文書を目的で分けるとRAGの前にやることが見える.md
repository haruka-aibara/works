# 社内文書を目的で分けると、RAG の前にやることが見える

社内文書を RAG で読ませる前に、文書の多くは古い。文書は何のためにあるのか、から考えると整理がつく。

## 文書の目的は4つ

| 目的 | 例 | 古くなるか |
|---|---|---|
| 伝える | 手順・構成・設計の説明 | なる。実態のキャッシュ |
| 決める | 規程・ルール・契約 | ならない。有効か失効か |
| 残す | 議事録・ADR・インシデント記録 | ならない。日付付きの記録 |
| 考える | 検討メモ・設計の下書き | 書き終えたら役目は終わり |

古くなるのは、ほぼ「伝える」だけ。**ただの設計やコーディングを人間向け文書に起こしたものは、実質的にキャッシュであり、実態を見ればいいだけ。** 実態は AI に読ませればいい。

## RAG の前に目的で分ける

4つが区別なく混ざり、RAG が全部を「今の正解」として引くのが問題。「伝える」は減らして実態を読ませ、「決める」は有効か失効かを出し、「残す」は日付付きで扱い、「考える」は閉じる。
