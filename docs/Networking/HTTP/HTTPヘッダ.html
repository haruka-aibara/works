HTTP ヘッダ

ブラウザとサーバは、本文を渡す前にまず「この通信の取扱説明」を交換している。それがヘッダ。トラブル調査で開発者ツールを開いたとき最初に読む場所でもある。

本文の前に付く「メタ情報」

HTML や JSON を送るだけなら本文だけでよさそうだが、実際には「どのホスト宛てか」「本文は何の形式でどのくらいの長さか」「キャッシュしていいか」といった、本文の外側の情報がないと双方が正しく処理できない。これを 名前: 値 の行の並びで先頭に付けるのが HTTP ヘッダ。

よく出てくるヘッダ

ヘッダ方向役割
Hostリクエストどのサイト宛てか（名前ベースのバーチャルホストの選別）
User-Agentリクエストブラウザ・クライアントの自己申告
Refererリクエストどのページから遷移してきたか
Content-Type両方ボディの形式（text/html、application/json など）
Locationレスポンスリダイレクト先（3xx とセット）
Set-Cookieレスポンスブラウザに Cookie を保存させる → Cookie の属性

セキュリティ関連のレスポンスヘッダ（Strict-Transport-Security など）はそれぞれ独立した仕組みなので、この表には含めていない。HSTS は別記事にある。
