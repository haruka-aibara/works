WebDAV

HTTP は基本「取りに行く」プロトコル。サーバ上のファイルを置く・消す・整理する——ファイルサーバの操作ができるように拡張したのが WebDAV。

HTTP のままファイルサーバとして使う

Web サーバ上のコンテンツを更新したいとき、本来の HTTP には手段がほぼない。かといって FTP など別プロトコルを併用すると、ポートも認証も別管理になる。WebDAV（Web-based Distributed Authoring and Versioning）は HTTP にメソッドを追加して、HTTP のポート（80/443）のままファイル操作をできるようにした拡張。ファイアウォールの設定も認証も TLS も、HTTP のものをそのまま使える。

使っていないなら無効にする。WebDAV は「HTTP でファイルを置ける」仕組みそのものなので、認証が甘いまま有効になっていると、攻撃者が Web サーバに任意のファイル（改ざんページや WebShell）を設置する入口になる。脆弱性診断で「WebDAV が有効」と指摘されるのはこのため。
