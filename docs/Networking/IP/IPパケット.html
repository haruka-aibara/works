IP パケット

LAN の外へ出るには、MAC アドレスでは足りない。世界中どこへでも届けるための単位。

MAC アドレスは「隣まで」しか使えない

イーサネットは同じネットワーク内の相手に MAC アドレスでフレームを届ける。だが世界中の機器の MAC アドレスを全ルータが覚えることはできないし、MAC アドレスには地理的・組織的な規則性がないので、「どっちの方向へ送ればいいか」を推測できない。

そこで階層構造を持った住所を別に用意し、それを頼りに中継する。この住所が IP アドレスで、IP アドレスを書いて運ばれるデータの単位が IP パケット。

届く保証はない

IP はベストエフォートで、次を保証しない。

  • 到達 — ルータが混雑していれば黙って捨てる
  • 順序 — 経路が分かれれば後から出たパケットが先に着く
  • 重複しないこと — 同じパケットが 2 つ届くこともある

これらを気にする通信は、上の層の TCP が面倒を見る。IP の仕事は「宛先の方向へ 1 歩進めること」だけ、と割り切られている。

大きすぎるパケットは分割される

経路上のリンクには通せる最大サイズ（MTU、イーサネットなら 1500 バイト）がある。それを超えるパケットはフラグメント化されて分割され、宛先で組み立て直される。

ただし分割は効率が悪く、1 片でも欠ければ全体が無駄になる。そのため実運用では、経路上の最小 MTU を探って最初からそのサイズで送る（Path MTU Discovery）のが普通。VPN や VXLAN でヘッダが増えた環境で通信が詰まるのは、ここが噛み合っていないことが多い。
