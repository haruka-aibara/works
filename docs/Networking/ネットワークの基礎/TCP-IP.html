TCP/IP

「Wi-Fi でも光回線でも同じアプリが動く」のはなぜか。役割を層に切り分けた設計の話。

全部を 1 つのプロトコルでやろうとすると破綻する

通信を成立させるには、電気信号の送り方から、隣の機器への渡し方、遠くのネットワークへの中継、欠けたデータの再送、そしてアプリケーション同士の約束事まで、性質のまったく違う仕事が必要になる。

これを 1 つの仕様に詰め込むと、無線が新しく登場するたびに Web ブラウザまで作り直す羽目になる。そこで仕事を層に分け、層と層の間のやりとりだけを決めておく。これが TCP/IP の考え方で、実際にインターネットで使われている 4 階層のモデルを指す。

層を通るたびにヘッダが増える

送信側では、上の層のデータに下の層が自分のヘッダを付けて渡していく。これをカプセル化という。受信側は逆に、下から順にヘッダを外して中身を上に渡す。
