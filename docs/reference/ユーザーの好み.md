# ユーザーの好み・判断軸

- **資格コンテンツの置き場所**：`Certifications/` のような横断バケツは作らない。試験範囲がそのままトピックになるもの（`IPA/`）は `docs/` 直下、特定トピックの資格はそのトピック配下に資格名のディレクトリを置く（`AI and Machine Learning/生成AIパスポート/`）
- **試験メモと解説記事は置き場所を分ける**：試験専用の学習計画・演習記録・要復習リストは `IPA/` 配下、そこから派生した汎用的な解説記事はトピック名の `docs/` 直下ディレクトリに置く
- **自分用の管理ファイルには学習状況を具体的に書く**：理解レベル・誤解の中身・受験目標・現在地を残す。ただし、配属先・案件名など仕事の固有情報は書かない
- **日本語話者のみが触る前提のリポジトリ設計では日本語を優先**：ADR のステータス等、慣習的に英語で書かれる定型語も日本語（有効/失効）にする。翻訳レイヤーを挟まない
- **AI 開発フローの検討は単一アカウント前提を好む**：マルチアカウント分離・SCP 等の組織側整備に踏み込まず、単一アカウントで完結する形を優先。AI は AWS に接続せず PR 作成まで、マージ・apply 以降は人間、という分担が基本線
- **通知設計は最小主義**：人間のチャンネルに流すのは「対応必須の新規検出」と「意図したリマインド」だけ。定期サマリ・ハートビート・カテゴリ外の情報は流さず、パイプラインの死活確認は CloudWatch 等の機械側に分離する
- **アーキテクチャ検討では敵対的セルフレビューを求める**：構成要素ごとに「本当に要るか」を問い、削れるものは削る方向で詰める（例：TrustedAdvisor 通知でイベント駆動レーン・週次サマリを廃止した経緯）
- **ツール紹介記事では「他の選択肢と比べてなぜそれか」を必ず書く**：同じ目的を果たす既存の仕組み（特に純正サービス）があるなら、それと並べて差分を示す。差分が薄いなら「そちらを使うほうが素直」と正直に書く。書かないと導入判断の記事として成立しない
- **「純正でもできる」ものは、できるかどうかではなく“自作して保守する量”で比較する**：Config のカスタムルール（Lambda / Guard）のような拡張余地がある以上、「純正では見られない」はたいてい不正確。正しい論点は「同じ検知を自分で何本書いて、誰が保守するか」。既製の検知ロジックが何個ついてくるかが差になる
- **比較するときは「何を検知できるか」の軸を最優先で立てる**：有効化の要否・課金・痕跡といった運用面の軸だけで並べると、「純正で足りるので要らない」という結論に倒れやすい。運用面が似ていても検知範囲が違うことが多く、そこが実際の決め手になる（例：Prowler は Lambda の環境変数や EC2 のユーザーデータの**値の中身**を読んで秘密を探すが、Trusted Advisor / Config / Security Hub CSPM は設定項目の準拠しか見ていない）

## AWS サービス名の表記

- **Security Hub は `Security Hub CSPM` と書く**：2025 年末に従来の AWS Security Hub は **AWS Security Hub CSPM** に改名され、「AWS Security Hub」は別の新サービスの名前になった。検知結果の集約とセキュリティ基準（CIS・FSBP）の準拠評価をしているのは CSPM のほう
- ただし **API・CLI・Terraform リソース名は `securityhub` / `aws_securityhub_*` のまま**。コード例・コマンド・URL は書き換えない。EventBridge の `detail-type` の文字列 `"Security Hub Findings - Imported"` も literal なのでそのまま

## ユーザーの立場・学習スタンス

ユーザーは **AWS セキュリティ DevOps エンジニア**。本業の専門領域はクラウドセキュリティだが、隣接領域（量子コンピュータ・AI・新興技術など）も**「専門家レベルではないが、知らないと話についていけない」程度には押さえておきたい**というスタンス。

このため、新興技術トピックを学ぶ際は以下を意識する：

- **深く広くではなく、浅く広く** の学習リソースを優先して提案する（数十時間の本格コースより、概念把握+業務接点が分かる短めの教材）
- **セキュリティ業務との接点を常に添える**。例：量子コンピュータなら耐量子暗号（PQC）・現行暗号への影響・AWS の PQC 対応状況など、本業に効く切り口を必ずセットで示す
- 「教養として知っておく」と「業務で使う」の境界を意識して、どちらの目的の学習かを確認してから提案する
