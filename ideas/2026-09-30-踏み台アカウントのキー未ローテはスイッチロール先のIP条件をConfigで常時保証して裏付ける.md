# 踏み台アカウントのキー未ローテは、スイッチロール先の IP 条件を Config で常時保証して裏付ける

踏み台（jump）アカウントの IAM ユーザーのアクセスキーは、規定の周期でローテされず残りがち。

これには「キーが漏れても、スイッチロール先の各環境ロールの信頼ポリシーに接続元 IP 条件があるので、許可範囲外からは悪用できない」と主張できる。
ただし「IP 条件のないロールを一つでも作ったら破綻するのでは」という反論が必ず来る。
IP 条件はロールを作るたびに人が書くものなので、ふつうは全ロールに付いていることを証拠で示す材料がない。

## やること

各環境ロールの信頼ポリシーを継続評価して、次の二点を常時保証する。

- `aws:SourceIp` 条件が存在する
- その値が許可レンジ内に収まっている

これで初めて代替統制が全ロールで効いていると言い切れ、ローテ未達の指摘への裏付けになる。
実装は Config のカスタムルール（Lambda）。

## 判定で気をつけそうなこと（未確認）

- 条件なしで踏み台を信頼する Allow 文が別にあれば素通りになる。踏み台を Principal に含む Allow 文すべてで見る
- 値は CIDR の包含で判定し、`0.0.0.0/0` などを弾く
- `NotIpAddress` の Deny で書く形も拾う
