# AccessDenied の急増は偵察のサイン

盗んだクレデンシャルで何ができるかを、攻撃者は総当たりで試す。
すると、同じ主体から短時間に `AccessDenied` が並ぶ。
ふだんの運用ではまず起きないので、**件数を数えるだけで誤検知の少ない検知**になる。

## SIEM で数える

1 件ずつ見るルールより、集計が得意な SIEM 向き。

- 「同じ主体（`userIdentity.arn` かアクセスキー）から、N 分で M 件以上の `AccessDenied`」で鳴らす
- 本当に危ないのは、**拒否が続いたあとに成功が出たとき**。通る権限を見つけたということなので、こちらは優先度を上げる
- 拒否された API の種類が多いほど総当たりらしい。件数より種類数で見るのもあり

## ノイズ

- 権限の少ない人がコンソールを開くと、画面の裏の読み取り API が大量に拒否される。人間のコンソール操作は除くか、しきい値を分ける
- 権限を絞った直後のアプリも拒否を出す。デプロイ直後は除外する

## GuardDuty との関係

GuardDuty にも、ふだんと違う API の呼び方を検知する finding がある（はず）。
SIEM で数えるのは、そこで拾えない分を補う位置づけ。

コンソールのノイズの出方と GuardDuty の finding は公式ドキュメント未確認。
