# EC2 の安全な既定値は SCP ではなく宣言型ポリシーで固定する

IMDSv2 の強制や AMI のパブリック共有禁止を SCP の条件キーで書くと漏れが出る。
Organizations の宣言型ポリシーなら、API ではなく設定の状態を固定できる。

## SCP との違い

- SCP は API 呼び出しを止める。新しい API や条件キー非対応の経路が出るとすり抜ける
- 宣言型ポリシーはサービス側の設定値を固定する。API が増えても効き続ける
- 止めたときにカスタムのエラーメッセージを出せる。「なぜ止められたか」の問い合わせが減る

## 固定できるもの（2024 年末の発表時点）

IMDSv2 必須 / AMI とスナップショットのパブリック共有ブロック / VPC のパブリックアクセスブロック / シリアルコンソール無効化 / 許可する AMI の制限

## 気をつけること

- 対象は EC2 まわりだけ
- IMDSv1 で動いている既存インスタンスがどうなるかは、試してから入れる
- 単一アカウントなら、同じ項目をアカウント単位の設定（`modify-instance-metadata-defaults` など）で固定できる
