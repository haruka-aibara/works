# ISMS のアクセス権レビューを Access Analyzer の未使用アクセスで回す

ISMS（ISO/IEC 27002 5.18）のアクセス権の見直しは、
権限一覧をスプレッドシートに出して上長が「問題なし」と書く儀式になりがち。
見る人に判断材料がないので、実質ノーチェックになる。

## 代わりに

IAM Access Analyzer の未使用アクセスの分析を使う。
一定期間使われていないロール・アクセスキー・パスワード・権限が検出結果として出る。

- レビュー対象を「使っていないのに持っている権限」に絞れる
- 検出結果を消化した記録が、そのまま見直しの証跡になる

## なぜ Credential Report や最終アクセス時刻ではなく

どちらも純正で取れるが、ロールごとに API を叩いて集計するスクリプトを自分で保守することになる。
Access Analyzer は組織全体を継続的に見るので、その集計を持たなくていい。

## 気をつけること

- 分析したロール・ユーザー数で月額課金。金額は未確認
- 「使っていない」と「要らない」は別。年 1 回のバッチや障害対応用のロールは除外するか期間を長くする
- 残すと判断した理由をどこに残すか。アーカイブルールで足りるかは未確認
