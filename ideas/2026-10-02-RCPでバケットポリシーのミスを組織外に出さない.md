# RCP でバケットポリシーのミスを組織外に出さない

SCP は「自分の組織のプリンシパルが何をできるか」しか縛れない。
外部のアカウントが自分の S3 バケットを読みに来るのは、バケットポリシー次第だった。

RCP（リソースコントロールポリシー）は、リソース側に上限をかける。
「組織外のプリンシパルは、組織内の S3・KMS・Secrets Manager などに触れない」を1枚で書ける。
**誰かがバケットポリシーで `"Principal": "*"` を書いても、組織外には出ない**。

## 例外が要るところ

- AWS サービス自身が触るもの（CloudTrail・Config・ALB のログ配信）。`aws:PrincipalIsAWSService` で除外する
- 取引先・委託先のアカウントに共有しているバケット。例外リストが RCP に並ぶのは、それ自体が棚卸しになる
- CloudFront の OAC 経由の配信

## 先にやること

IAM Access Analyzer の外部アクセス検出で、いま組織外に出ているものを洗う。
出ているものを把握してから RCP を入れないと、本番の連携が黙って止まる。

対応サービスは S3・STS・KMS・SQS・Secrets Manager から始まり、増えているはず（未確認）。
