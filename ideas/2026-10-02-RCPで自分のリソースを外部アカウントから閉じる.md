# RCP で「自分のリソース」を外部アカウントから閉じる

SCP は組織の中の人ができることを縛る。
外部アカウントが、うちの S3 バケットや KMS キーに入ってくるのは止められない。
それを止めるのが RCP（Resource Control Policies）。

組織外のプリンシパルからの `s3:*` などを、`aws:PrincipalOrgID` が自組織でなければ Deny する。
これを組織のルートに付ければ、誰かがバケットポリシーを `"Principal": "*"` にしても組織外からは入れない。

リソースポリシーを1つずつ Config で検知して直す代わりに、上から塞ぐ。
[予防で通知を減らす](./2026-09-26-通知が多いセキュリティアラートを予防で減らす.md) の典型例になりそう。

## 例外の持ち方が本題

外部と正当に共有しているものが必ずある。

- AWS サービス自身のアクセス（`aws:PrincipalIsAWSService` で除く）
- 取引先との S3 共有、SaaS ベンダーへの AssumeRole

例外を条件キーやタグでどう書くかで、保守できるかが決まる。
先に Access Analyzer の外部アクセス検出で「いま外部に開いているもの」を棚卸しし、例外の一覧を作ってから付ける。

対応サービスは S3・KMS・STS・SQS・Secrets Manager から増えているはず。最新は未確認。
