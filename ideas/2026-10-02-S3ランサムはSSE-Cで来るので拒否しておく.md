# S3 ランサムは SSE-C で来るので拒否しておく

S3 のランサムウェアは、データを持ち出さなくても成立する。
漏れたアクセスキーで、**攻撃者が持っている鍵を使って SSE-C で上書き**するだけ。
AWS 側に鍵が残らないので戻せない。

2025 年初めに「Codefinger」として報告された手口（一次情報は未確認）。

## 塞ぎ方

- 自分たちが SSE-C を使っていないなら、使わせない。条件キー `s3:x-amz-server-side-encryption-customer-algorithm` が付いた `PutObject` を Deny する
- 単一アカウントならバケットポリシー、組織なら SCP か RCP
- バージョニングがあれば、上書き前の版は残る。ライフサイクルで旧版をすぐ消していなければ
- 削除と上書きの両方に耐えたいなら、結局 Object Lock

## 確認したいこと

- AWS が新規バケットで SSE-C をデフォルト無効にする話があったはず。時期と既存バケットの扱いは未確認
- 外部アカウントの KMS キーで暗号化させる亜種もありうる。`s3:x-amz-server-side-encryption-aws-kms-key-id` で自アカウントのキーに絞れるか
