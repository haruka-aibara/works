# S3 署名付き URL の寿命をバケットポリシーで縛る

署名付き URL の有効期限は発行側が決める。
IAM ユーザーのアクセスキーで署名すると最長 7 日で、チャットに貼られた URL が 1 週間生きる。

バケットポリシーで `s3:signatureAge`（署名からの経過ミリ秒）に上限をかけると、
発行側が長く設定しても、**バケット側で一律に短くできる**。

```json
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::example-bucket/*",
  "Condition": { "NumericGreaterThan": { "s3:signatureAge": "600000" } }
}
```

## 気をつけること

- 署名付き URL 以外のリクエスト（SDK・コンソール）も SigV4 なので同じ条件にかかる。長時間かかる処理が巻き込まれないか確認
- 一時クレデンシャルで署名した URL は、そのセッションの期限で先に切れる
- `s3:authType` で `REST-QUERY-STRING`（クエリ文字列の署名）だけに絞れるはず。未確認
