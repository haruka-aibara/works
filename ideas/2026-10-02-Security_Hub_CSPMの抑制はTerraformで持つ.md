# Security Hub CSPM の抑制は Terraform で持つ

Security Hub CSPM の検知を「対応しない」と決めたとき、コンソールで Suppressed にすると理由が残らない。
半年後に「なぜこれを抑制したのか」が誰にも分からなくなる。

自動化ルール（`aws_securityhub_automation_rule`）で抑制を書けば、
**抑制の理由が PR とコミットメッセージに残り、レビューも通る**。

## 書き方の方針

- ルール1本 = 抑制の理由1つ。`description` に理由、条件にリソース ARN やタグを書く
- 「開発アカウントの低重要度はすべて抑制」のような広いルールは避ける。何を捨てたか見えなくなる
- 期限つきの抑制は、コメントに期限を書いて、Renovate や定期 Issue で見直しを促す

## 意図を残す話とつながる

検知結果の状態はコンソールを見れば分かる（キャッシュで足りる）。
残らないのは「なぜ抑制したか」のほうなので、そこだけをコードに書く。
