# Security Hub CSPM の抑制は Terraform の自動化ルールでレビューに乗せる

コンソールで検出結果を「抑制」すると、誰がなぜ抑制したかが残りにくい。
半年後に見ると、正しい判断だったのか、面倒で黙らせたのかが分からない。

自動化ルール（`aws_securityhub_automation_rule`）で抑制を書けば、抑制が PR になる。
理由はコミットとレビューに残り、ルールの削除で抑制を戻せる。

## 運用の形

- コンソールでの手動抑制は禁止し、IAM で `BatchUpdateFindings` を人間から外す
- 自動化ルールの `description` に理由と期限を書く
- 期限切れのルールは CI で落とす（期限の持ち方は要検討）

## 予防との関係

抑制は「対応不要と分かっているノイズ」に限る。
[通知が多いアラートは予防で減らす](2026-09-26-通知が多いセキュリティアラートを予防で減らす.md) が先で、抑制はその残り。
PR にしておけば、抑制が増えてきたこと自体がレビューで見える。
