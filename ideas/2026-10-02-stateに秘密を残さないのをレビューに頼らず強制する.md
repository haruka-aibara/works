# state に秘密を残さないのを、レビューに頼らず強制する

write-only 引数（`value_wo` など）を使えば秘密は state に残らない。
問題は**全員がそれを守り続けるか**。レビューで見落とさない前提にせず、機械で止める。

## plan の時点で止める

plan の JSON にポリシーを当てる（OPA / Sentinel、CI なら conftest）。

- SSM の SecureString は `value` 禁止、`value_wo` 必須
- RDS は `password` 禁止、`manage_master_user_password` か `password_wo` 必須
- `random_password` は ephemeral 版以外、`aws_iam_access_key` は警告

## 対応したら必須に上げる

未対応のリソースはまず警告（Sentinel の advisory）で入れ、provider に `_wo` が増えたら必須（hard-mandatory）に上げる。
気づき遅れないよう、`terraform providers schema -json` の `write_only` 属性を前の版と比べ、増えたら知らせる。

## すり抜けたものを拾う

既存の state を定期的に読み、`sensitive_attributes` の付いた属性を数える。増えていたらすり抜けがある。

Terraform が発行するトークンなど外せない秘密は、state を読める人を絞って守る。

OPA / Sentinel が使えるプラン、schema と state の JSON の形は未確認。
