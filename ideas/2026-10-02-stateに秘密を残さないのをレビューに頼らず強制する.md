# state に秘密を残さないのを、レビューに頼らず強制する

write-only 引数（`value_wo` など）を使えば秘密は state に残らない。
問題は**全員がそれを守り続けるか**。レビューで見落とさない前提にせず、機械で止める。

## plan の時点で止める

plan の JSON にポリシーを当てる（HCP Terraform の OPA / Sentinel、または CI で conftest）。

| ルール | 理由 |
|---|---|
| SSM の SecureString は `value` 禁止、`value_wo` 必須 | 一番よくある漏れ方 |
| RDS は `password` 禁止、`manage_master_user_password` か `password_wo` 必須 | マスターパスワード |
| `random_password` は ephemeral 版以外を警告 | 作った値が残る |
| `aws_iam_access_key` は警告 | 長期キーの発行自体を見直す |

tflint のカスタムルールでもできるが、plan の JSON なら実際に入るもので判定できる。

## すり抜けたものを拾う

既存の state を定期的に読み、`sensitive_attributes` の付いた属性を数える。増えていたらすり抜けがある。

## 外せない秘密

Terraform が発行するトークンなどは残るしかない。state を読める人を絞り、読んだ記録を残す。

OPA / Sentinel が使えるプランと、state の JSON での `sensitive_attributes` の形は未確認。
