# アカウントの既定値で予防できるものを先に全部 ON にする

Config や Security Hub CSPM で「違反を検知して直す」前に、
アカウント（リージョン）単位の既定値で**そもそも違反を作れなくする**ものを全部 ON にする。
[通知が多いアラートを予防で減らす](2026-09-26-通知が多いセキュリティアラートを予防で減らす.md) の一番安い打ち手。

## Terraform で 1 リソースずつ

| 予防するもの | リソース（provider のバージョン要確認） |
|---|---|
| EBS の暗号化忘れ | `aws_ebs_encryption_by_default` |
| S3 の公開 | `aws_s3_account_public_access_block` |
| AMI の公開 | `aws_ec2_image_block_public_access` |
| EBS スナップショットの公開 | `aws_ebs_snapshot_block_public_access` |
| IMDSv1 の EC2 | `aws_ec2_instance_metadata_defaults` |

S3 以外は**リージョンごと**なので、使っていないリージョンにも provider の alias で撒く。

## 敵対的に見ると

- 既定値は「新しく作るもの」にしか効かないものがある。既存の違反は別途 Config で一度洗う
- IMDS の既定値は起動時の値を上書きされると負ける。ここだけは SCP や Config で塞ぐ側も要る
- 入れて困るのは「公開が正しい」もの（公開 AMI の配布など）。あるなら例外を先に棚卸しする
