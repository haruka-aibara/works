# スナップショットと AMI の持ち出しは公開ブロックでは止まらない

EBS スナップショットと AMI のパブリックアクセスブロックが止めるのは「全員に公開」だけ。
攻撃者が**自分のアカウント ID を指定して共有する**のは公開ではないので素通りする。
宣言型ポリシーで組織全体に強制していても同じ。

## 単一アカウントでの塞ぎ方

- EBS の既定の暗号化をカスタマー管理キーにし、キーポリシーで外部アカウントに使わせない。共有されても相手は復号できない
- AWS マネージドキー（`aws/ebs`）で暗号化したものは、そもそも他アカウントに共有できない（はず）
- それでも、強い権限を盗まれたらキーポリシーを書き換えられる。暗号化されていない古いスナップショットも残る。最後の一枚として `ec2:ModifySnapshotAttribute` と `ec2:ModifyImageAttribute` を Deny する

## Organizations 配下での塞ぎ方

| 手段 | 何をするか |
|---|---|
| RCP（KMS） | キーの利用者を `aws:PrincipalOrgID` で組織内に絞る。各アカウントのキーポリシーを直さずに一律でかかる |
| SCP | 共有の API を Deny。`ec2:Add/userId` で共有先が許可リスト外のときだけ Deny できる（はず） |

暗号化されていないものは RCP で守れないので、SCP と組で使う。

`ec2:Add/userId` が使えるかと、RCP の KMS 対応は公式ドキュメント未確認。
