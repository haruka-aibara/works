# セキュリティの例外には期限を付ける

Security Hub CSPM の抑制、Config 非準拠の放置、Prowler の Mutelist。
どれも一度例外にすると、誰も見直さずに残り続ける。
書いた人が異動したら、なぜ例外なのか誰にも分からない。

例外を作るときに「いつまで」を必須にし、期限が来たら例外を外して再び通知させる。

## やり方の案

- リソースに `security-exception-until = 2027-03-31` と `security-exception-reason` のタグを付ける
- Security Hub CSPM の自動化ルールで、タグ付きの検出結果を抑制する
- 日次の Lambda で期限切れを見つけたら抑制を戻す

期限が来たら「延長か、直すか」を決め直す。
延長には理由を書き直す手間がかかるのが、むしろいい。

## 気になること

- 抑制自体には期限を持たせられない（はず）ので、期限は自前で持つ
- タグを付けられないリソースや、アカウント単位の検出結果はどうするか
- [Config 非準拠のリマインド](../docs/Amazon%20Web%20Services/04_セキュリティ/検知と可視化/Config非準拠を定期リマインドで減らす.md) と仕組みを一本化できないか

自動化ルールがリソースのタグを条件に取れるかは未確認。
