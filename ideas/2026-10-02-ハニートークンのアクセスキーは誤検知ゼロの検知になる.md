# ハニートークンのアクセスキーは誤検知ゼロの検知になる

使われるはずのないアクセスキーをわざと置いておき、使われたら即アラートにする。
正規の利用者が存在しないので、鳴ったら 100% 何かが起きている。
「対応必須の新規検出だけ通知する」方針と相性がいい。

## 置き場所の例

- CI の環境変数、古い wiki、社内リポジトリの「うっかりコミット」風のファイル
- どこから漏れたか分かるよう、置き場所ごとに別のキーにする

## 作り方

- 本番と切り離した専用アカウントに、権限なし（全部 Deny）の IAM ユーザーを作ってキーを発行する
- 権限がなくても API を叩けば CloudTrail に `AccessDenied` で残るので、そのユーザーのイベントを EventBridge で拾って通知する
- 自前で持ちたくなければ Thinkst の Canarytokens が AWS キー型を無料で出している

## 弱いところ（未確認）

- 攻撃者側も知っていて、CloudTrail に残らない方法でキーの持ち主アカウントを調べる手口が出回っている。名前が「いかにも」だと触らずに捨てられる
- 鳴った後は [クレデンシャル漏洩後の初動対応](../docs/Amazon%20Web%20Services/04_セキュリティ/IAM/クレデンシャル漏洩後の初動対応.md) の手順に乗せる
