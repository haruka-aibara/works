# メンバーアカウントの root は消して、必要なときだけ AssumeRoot する

エンタープライズで地味に重いのが、アカウントの数だけある root のパスワードと MFA デバイスの保管。
Organizations の root アクセス一元管理を使えば、メンバーアカウントの root 認証情報そのものを消せる。

## 何が変わるか

- メンバーアカウントの root パスワード・アクセスキー・MFA を削除できる。新規アカウントは最初から root 認証情報なしで作れる
- root でしかできない作業は、管理アカウント（か委任先）から `sts:AssumeRoot` で、タスク単位の短命セッションを取って行う
- 「自分をロックアウトした S3 バケットポリシーを消す」のような作業がタスクとして用意されている

MFA トークンを金庫で棚卸しする運用が要らなくなる。

## 気をつけるところ

- 管理アカウント自身の root は対象外。そこだけは従来どおり守る
- `AssumeRoot` を誰が呼べるかが新しい急所になる。SCP で絞り、CloudTrail で呼ばれたら必ず見る（これは数少ない「毎回通知していい」イベント）
- root でしかできない作業のうち、タスクとして用意されていないもの（未確認）はパスワード復旧で一時的に root を戻す手順になりそう
