# メンバーアカウントのルートユーザーは認証情報ごと消す

メンバーアカウントのルートに MFA を付けて金庫にしまう運用は、アカウントの数だけ MFA とパスワードを抱える。
Organizations の「ルートアクセスの一元管理」で、認証情報ごと消すほうが筋がいい。

## 何ができるか

- メンバーアカウントのルートのパスワード・アクセスキー・MFA を削除する。新規アカウントは最初から持たない
- ルートでしかできない作業（締め出しバケットポリシーの削除など）は、管理アカウントから `sts:AssumeRoot` で一時的にやる
- ルート MFA の棚卸しと、Security Hub CSPM のルート MFA 系の検出が要らなくなる

## なぜ SCP で Deny するだけではだめか

SCP は API 操作を止めるが、認証情報は残る。
消せば、パスワードリセットや MFA 紛失の対応ごと守る対象がなくなる。

## 気をつけること

- 管理アカウントのルートは対象外
- `AssumeRoot` でできる作業は限られる。アカウント解約などの扱いは未確認
- `AssumeRoot` を誰に許すかが新しい急所になる。使われたら必ず通知する
