# 他人のバケットに書き込まないよう aws:ResourceAccount で縛る

S3 のバケット名はグローバルに一意なので、攻撃者が先に同じ名前を取れば、自分のデータがそっちに流れる。
2024 年に「Bucket Monopoly」として、CDK のブートストラップバケットや一部サービスの予測可能なバケット名が狙えると発表された。

守る側は「バケットは自分で作っているから大丈夫」と考えがちだが、
消したバケットの名前、別リージョン、まだ作っていない環境のバケット名は他人が取れる。

## 対策

- 人間・CI のロールに、`aws:ResourceAccount` が自組織（または自アカウント）でない S3 操作を Deny する
- 組織なら SCP、単一アカウントなら Permission Boundary か各ロールのポリシーに書く
- AWS サービスが裏で使うバケット（Athena の結果、Glue など）が外れないかは試してから広げる

## データ境界の残り半分

- 「外から自分のリソースに入られない」は RCP や Block Public Access で守る
- 「自分が外のリソースに出ていかない」がこっち。忘れられやすい

Claude が出したアイデアで、Bucket Monopoly の対象サービスと修正状況は未確認。
