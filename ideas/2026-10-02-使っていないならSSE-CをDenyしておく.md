# 使っていないなら SSE-C を Deny しておく

攻撃者が、盗んだクレデンシャルで S3 のオブジェクトを**自分の鍵（SSE-C）で暗号化し直して上書きし**、鍵と引き換えに身代金を取る手口がある。
SSE-C の鍵は AWS に保存されないので、AWS に頼んでも復号できない。
2025 年 1 月に報告された Codefinger の手口（はず）。

自分たちが SSE-C を使っていないなら、使えなくしておけば手口ごと潰せる。

## 塞ぎ方

バケットポリシーで、SSE-C のヘッダー付きの `PutObject` を Deny する。

```json
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:PutObject",
  "Resource": "arn:aws:s3:::example-bucket/*",
  "Condition": {
    "Null": { "s3:x-amz-server-side-encryption-customer-algorithm": "false" }
  }
}
```

Terraform のバケット用モジュールの既定に入れる。

## 気をつけること

- バケットの暗号化設定で SSE-C をブロックする設定ができ、2026 年 4 月ごろから新しいバケットでは既定でブロックされる、と聞いた。既存バケットの扱いも含め公式ドキュメント未確認
- 止まるのは SSE-C での上書きだけ。削除して脅す経路はバージョニングと Object Lock で塞ぐ
- 使っていないかは、CloudTrail のデータイベントかサーバーアクセスログで確かめてから入れる
