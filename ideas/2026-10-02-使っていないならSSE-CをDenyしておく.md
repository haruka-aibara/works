# 使っていないなら SSE-C を Deny しておく

攻撃者が、盗んだクレデンシャルで S3 のオブジェクトを**自分の鍵（SSE-C）で暗号化し直して上書きし**、鍵と引き換えに身代金を取る手口がある。
SSE-C の鍵は AWS に保存されないので、AWS に頼んでも復号できない。
2025 年 1 月に Codefinger という名前で報告された（はず）。

自分たちが SSE-C を使っていないなら、使えなくしておけば手口ごと潰せる。

## 塞ぎ方

バケットポリシーで、SSE-C のヘッダー付きの `PutObject` を Deny する。

```json
{
  "Effect": "Deny",
  "Principal": "*",
  "Action": "s3:PutObject",
  "Resource": "arn:aws:s3:::example-bucket/*",
  "Condition": {
    "Null": { "s3:x-amz-server-side-encryption-customer-algorithm": "false" }
  }
}
```

全バケットに撒くのは漏れが出るので、Terraform のモジュールの既定に入れる。

## 気をつけること

- バケットの暗号化設定で SSE-C をブロックする設定ができ、2026 年 4 月ごろから新しいバケットでは既定でブロックされる、と聞いた。既存バケットがどうなるかも含めて未確認
- Deny で止まるのは上書きだけ。オブジェクトを消して身代金を取る経路は、バージョニングと Object Lock で別に塞ぐ
- 本当に使っていないかは、CloudTrail のデータイベントか S3 のサーバーアクセスログで確かめてから入れる
