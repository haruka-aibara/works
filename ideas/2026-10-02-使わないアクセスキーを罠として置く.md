# 使わないアクセスキーを罠として置く

権限ゼロの IAM ユーザーを作り、アクセスキーをわざと「漏れたら困りそうな場所」に置いておく。
社内 Wiki、古いリポジトリの `.env`、踏み台の `~/.aws/credentials` など。

正規の利用者は誰も使わないので、**このキーで API が1回でも叩かれたら、それだけで侵害確定**。
誤検知がほぼゼロなので、通知を増やさない。

## 仕組み

- 権限はゼロ（明示 Deny を付けておくとなお安心）。叩かれても失敗するだけ
- CloudTrail の `userIdentity.accessKeyId` で EventBridge を張り、即通知
- 失敗した呼び出しや `sts:GetCallerIdentity` も拾える

## 面白いところ

- GuardDuty は「普段と違う」を確率で拾うが、これは**使われた瞬間に確定**する
- どの置き場所のキーが叩かれたかで、**どこから漏れたか**まで分かる。置き場所ごとにキーを分ける

## 気をつけること

- 攻撃者もユーザー名などで罠を見分けようとするらしい。名前は本物っぽくする
- IAM ユーザーを作ること自体が「IAM ユーザー禁止」の Config ルールに引っかかる。例外として明示する

Thinkst の Canarytokens が同じ発想。自前で作るか既製品を使うかは要比較（未確認）。
