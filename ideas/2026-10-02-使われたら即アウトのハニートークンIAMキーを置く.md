# 使われたら即アウトのハニートークン IAM キーを置く

権限ゼロの IAM ユーザーのアクセスキーを、漏れそうな場所にわざと置いておく。
正規の利用者は絶対に使わないので、このキーで API が叩かれたら 100% 侵害か漏洩。
誤検知がほぼ出ないので、通知最小主義とも相性がいい。

## 置き場所の候補

- 開発者 PC の `~/.aws/credentials` に `[prod-admin]` のようなそれっぽいプロファイル名で
- CI の環境変数、社内 Wiki の古い手順書、使っていない private リポジトリ

どこに置いたキーかを台帳にしておけば、発火したキーから漏れた経路まで特定できる。

## 検知

- CloudTrail の `userIdentity.accessKeyId` で EventBridge ルールを張り、Slack に直送
- 権限ゼロでも `AccessDenied` のイベントは記録されるはず
- 攻撃者は最初に `sts:GetCallerIdentity` で確かめることが多い。これが CloudTrail に残るかは要確認

## 気をつけること

- 本物のキーなので「権限ゼロ」を Permission Boundary や SCP でも担保する
- Thinkst Canarytokens のような既製品もある。自前で持つのは EventBridge ルール 1 本なので、保守量で比べると自作でも軽い

Claude が出したアイデアで、CloudTrail の記録範囲は公式ドキュメント未確認。
