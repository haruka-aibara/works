# 使われたら即アウトのハニートークンのアクセスキーを撒く

権限ゼロの IAM ユーザーのアクセスキーを、わざと盗まれそうな場所に置いておく。
正規の利用者はいないので、CloudTrail にそのキーの呼び出しが1件でも出たら、誤検知なしで侵入と判断できる。

## 撒く場所の候補

- 開発端末の `~/.aws/credentials` に、それっぽいプロファイル名で
- 社内 Wiki・チケット・private リポジトリの古そうな設定ファイル

GuardDuty は「おかしな動き」を推定で拾うが、これは「触った時点で黒」。
通知が多いのが悩みの運用でも、件数がほぼゼロなので最小主義と相性がいい。

## 気になる点（未確認）

- 読み取り系（`sts:GetCallerIdentity` など）の呼び出しを EventBridge で拾うには、オプトインが要ったはず。拾えないなら CloudWatch Logs のメトリクスフィルタで
- 攻撃者は CloudTrail に残らない API でキーの持ち主を調べる手口を使うと聞いた。全部は拾えない前提で置く
- Thinkst の Canarytokens のような既製品はアカウント ID が知られていて見破られやすいらしい。自前で作るほうがいい理由はここ
- 権限ゼロでも、キー自体はアクセスキー棚卸しの指摘に引っかかる。除外ルールが要る
