# 使われたら即事故と分かるカナリアのアクセスキーを撒く

権限ゼロの IAM ユーザーのアクセスキーを、漏れそうな場所に置いておく。
そのキーで API が叩かれた時点で、その場所から漏れたことが確定する。

## 置き場所

- CI のシークレット、社内 Wiki、Terraform の state を置いているバケット
- 場所ごとにキーを分ける。どのキーが鳴ったかで漏れた場所が分かる

## なぜ GuardDuty だけでは足りないか

GuardDuty は「普段と違う使われ方」を確率で見る。
カナリアは使われたこと自体が異常なので、誤検知がほぼない。
鳴ったら必ず対応が要る通知しか出ないので、通知を最小にしたい方針と合う。

## 作り方

- 全 Deny のポリシーだけを付ける。Deny でも CloudTrail に `AccessDenied` の記録が残る
- 組織の証跡を CloudWatch Logs に送り、`accessKeyId` でメトリクスフィルタを張る。全リージョンを拾うため
- 鳴った後は [クレデンシャル漏洩後の初動対応](../docs/Amazon%20Web%20Services/04_セキュリティ/IAM/クレデンシャル漏洩後の初動対応.md) と同じ

## ただし

CloudTrail に記録されない API でキーの生死だけ確かめる手口が知られている。
どこまで塞がっているかは未確認。
