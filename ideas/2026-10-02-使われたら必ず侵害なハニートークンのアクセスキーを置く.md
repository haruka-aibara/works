# 使われたら必ず侵害な、ハニートークンのアクセスキーを置く

権限ゼロの IAM ユーザーを作り、そのアクセスキーを「盗まれそうな場所」に置く。
このキーが API を叩いたら、100% 侵害の兆候。
誤検知がないので、通知は対応必須だけという方針とぶつからない。

## 置き場所の候補

- 社内 Wiki の「昔の手順書」っぽいページ
- 開発端末の `~/.aws/credentials` に `[prod-old]` のようなプロファイル名で
- 社内リポジトリの古いブランチ、CI の変数

場所ごとに別ユーザーにすれば、どこから漏れたかまで分かる。

## 検知

権限がないので API は AccessDenied になるが、CloudTrail には残る。
EventBridge で該当ユーザーのイベントを拾って通知するだけ。

## 気をつけること

- 公開リポジトリには置かない。AWS が漏洩を検知して隔離ポリシーを付け、連絡が来て騒ぎになる
- 攻撃者は CloudTrail に残らない API でキーの有効性だけ確かめることがある。拾えたら儲けものくらいに置く
- 自前でやるほどでなければ Thinkst の Canarytokens に AWS キーの種類がある

どの API が CloudTrail に残らないかは未確認。
