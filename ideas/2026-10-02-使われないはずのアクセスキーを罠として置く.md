# 使われないはずのアクセスキーを罠として置く

権限ゼロの IAM ユーザーを作り、アクセスキーを「漏れたら困りそうな場所」に置いておく。
CI の設定ファイル、社内 Wiki、開発者 PC の `~/.aws/credentials` など。

正規の利用者は誰も使わないので、このキーで API が叩かれたら、それだけで侵害の兆候になる。
誤検知がほぼゼロなので、「通知は対応必須のものだけ」という方針と相性がいい。

## 仕組み

- 権限はつけない。Deny されても CloudTrail には `AccessDenied` で記録が残る
- EventBridge で `userIdentity.accessKeyId` が罠のキーと一致したら通知する
- どこに置いたキーかを管理しておけば、どの経路から漏れたかまで分かる

## 気をつけること

- CloudTrail に記録されない API がある。攻撃者はキーの生死をそれで確かめにくる、という話を聞いた（Thinkst Canary 周りの話）。どの API が該当するかは未確認
- 置き場所ごとにキーを分けるとユーザーが増える。IAM ユーザー作成を禁じる SCP がある組織では例外の扱いを決める
