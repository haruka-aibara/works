# 使われないアクセスキーを撒いて漏洩を検知する

権限ゼロの IAM ユーザーのアクセスキーを、漏れそうな場所にわざと置いておく（ハニートークン）。
正規の利用者は誰も使わないので、**このキーで API が1回でも叩かれたら、それだけで漏洩が確定する**。
誤検知がほぼなく、通知最小主義と相性がいい。

## 置き場所の例

- 社内 Git・CI の変数・Wiki・踏み台の `~/.aws/credentials`
- 置き場所ごとにキーを分けると、どこから漏れたかまで分かる

## 検知の仕組み

- 権限がなくても、拒否された呼び出しは CloudTrail に残る。攻撃者がまず叩く `sts:GetCallerIdentity` も残るはず
- CloudTrail → EventBridge で `userIdentity.userName` を拾って通知する
- EventBridge は読み取り系（Get / List / Describe）のイベントを既定で流さない、という話がある。流れないなら CloudWatch Logs のメトリクスフィルタで拾う（未確認）

## 気をつけること

- 外部の Canarytokens はアカウント ID が知られていて、見抜く攻撃ツールがある。自社アカウントで作るほうがバレにくい
- 逆に、キーからアカウント ID が分かるので、どの会社のキーかは攻撃者に伝わる
