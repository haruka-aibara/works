# 使われないアクセスキーを置いて、触られたら鳴らす

権限ゼロの IAM ユーザーのアクセスキーを「それっぽい場所」に置いておく。
誰も使わないので、使われた時点で漏洩が確定する。
誤検知が原理的に出ない、珍しいアラートになる。

通知を対応必須のものだけに絞る方針とも合う。

## 置き場所の候補

- 開発者 PC の `~/.aws/credentials` に `[prod-admin]` のような名前で
- 社内 Wiki・Confluence の古い手順書
- CI の環境変数・コンテナイメージの中

置き場所ごとにユーザーを分ければ、漏れた経路も分かる。

## 検知

- 権限がなくても、キーを使った API 呼び出しは AccessDenied として CloudTrail に残る
- EventBridge で `userIdentity.accessKeyId` を拾って通知する
- 攻撃者は最初に `sts get-caller-identity` を叩くことが多い。これは権限がなくても成功し、CloudTrail にも残るはず

## 気をつけること

- 攻撃者側もこの手口を知っていて、ユーザー名やアカウント ID でハニートークンを見分けようとする。名前は本物に寄せる
- 自作せず Thinkst Canarytokens の AWS キーを使う手もある。通知は外部サービス経由になる

CloudTrail の記録のされ方（特に `get-caller-identity`）は未確認。
