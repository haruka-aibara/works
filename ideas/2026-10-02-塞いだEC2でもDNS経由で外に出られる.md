# 塞いだ EC2 でも DNS 経由で外に出られる

セキュリティグループもネットワーク ACL も、VPC 内の DNS リゾルバ（`.2`）への問い合わせは止められない。
リゾルバは解決できない名前を外の権威 DNS に転送するので、**外向き通信を全部塞いだ EC2 でも、名前解決の経路だけは外につながっている**。

これを悪用するのが DNS トンネリング。解決させる名前に情報を載せ、リゾルバ越しに少量のデータを外へ出す（持ち出し・C2 のビーコン）。帯域は細いが「egress を塞いだから安心」が崩れる。

## 防御

- **Route 53 Resolver DNS Firewall** で、許可したドメイン以外への問い合わせをブロックする。これが正面の対策
- Resolver のクエリログで、1 つのドメインへの異常に多い・長いサブドメインのクエリを見る。量とサブドメイン長に癖が出る
- 外向き DNS を VPC リゾルバだけに寄せ、EC2 が外部 DNS を直接引けないようにする

## 気をつけること

- ネットワーク ACL で本当に `.2` 宛てが素通りするかは、実挙動で確かめる
- GuardDuty にも DNS 経由の持ち出しや C2 を検知する finding がある（はず）。DNS Firewall で塞ぎつつ、検知はそちらでも拾う

ネットワーク ACL の挙動と GuardDuty の finding は公式ドキュメント未確認。
