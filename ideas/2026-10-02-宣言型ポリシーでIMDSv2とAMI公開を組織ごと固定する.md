# 宣言型ポリシーで IMDSv2 と AMI 公開を組織ごと固定する

Organizations の宣言型ポリシー（Declarative policies）は、SCP と違って API を拒否するのではなく、サービスの設定そのものをアカウント全体で固定する。
EC2 なら、IMDSv2 の強制、AMI・スナップショットのパブリック共有のブロック、シリアルコンソールの無効化などを組織単位でかけられる。

## SCP や Config との違い

- SCP で `ec2:RunInstances` に条件を付ける方式は、条件キーの書き漏れや新しい API で抜けがある
- Config で検知して直す方式は、作られてから気づく
- 宣言型ポリシーは設定値として固定されるので、新しい API が増えても効くはず。違反時のエラーメッセージも独自に出せる

## 気をつけること

- IMDSv1 前提の古いエージェントやコンテナ（ホップ数制限）が動かなくなる。まず「設定の現状レポート」でどのアカウントに影響が出るか見てから適用する
- 対象は EC2 まわりの一部設定だけ。何でもできるわけではない
