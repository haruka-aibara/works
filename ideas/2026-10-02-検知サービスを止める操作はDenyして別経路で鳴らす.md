# 検知サービスを止める操作は Deny して別経路で鳴らす

侵入した攻撃者は、最初に GuardDuty・Config・Security Hub CSPM・CloudTrail を止めて検知を潰しにくる。

## 塞ぐ

Terraform の実行ロール以外は、止める操作を Deny する。

- `guardduty:DeleteDetector`、`guardduty:UpdateDetector`（無効化）
- `config:StopConfigurationRecorder`、`config:DeleteConfigurationRecorder`
- `securityhub:DisableSecurityHub`
- `cloudtrail:StopLogging`、`cloudtrail:DeleteTrail`

## 鳴らす：止まったことを本人には言わせない

GuardDuty は CloudTrail の停止などを `Stealth:` 系の finding で出すが、**自分自身が消されたら finding を出せない**。
止まったことの検知は、止められる側とは別の経路に置く。

- CloudTrail の管理イベントを EventBridge で拾い、上の API が呼ばれたら鳴らす
- Config の「GuardDuty が有効か」のルールは、Config ごと止められると一緒に黙る。主にはしない

## 組織なら

GuardDuty を委任管理者から管理していれば、メンバーアカウント側では無効化できない（はず）。
SCP で止める操作を Deny すれば、メンバーの管理者権限でも止まる。

GuardDuty の finding 種類と、委任管理者配下での挙動は公式ドキュメント未確認。
