# 消したリソースを指す DNS レコードを探す

リソースを消しても、Route 53 のレコードは残る。
残ったレコードの指す先を他人が取れると、**自社のサブドメインで他人のコンテンツが出る**（サブドメイン乗っ取り）。

## 取られうる指し先

- S3 の静的サイト：バケット名はグローバルなので、消した名前を他人が作れる
- Elastic IP：解放した IP は他の AWS 利用者に払い出される。A レコードが残っていれば乗っ取り
- Elastic Beanstalk の CNAME：環境名を他人が取れる
- CloudFront：代替ドメイン名の重複は防がれるはずだが、未確認

## 探し方

1. Route 53 の全ホストゾーンから A / CNAME / ALIAS を抜く
2. 指し先が自アカウントに今あるかを突き合わせる（EIP 一覧、バケット一覧、ELB 一覧）
3. 自分のものではない指し先が残っていたら即削除

## Terraform との関係

Terraform でリソースとレコードを同じ state に置いていれば、一緒に消える。
問題になるのは、レコードだけ手で作った・別の state にある場合。
DNS は別チームという企業ほど起きやすい。

S3 なら、バケット名にアカウント ID を入れておけば他人は同じ名前を予測しにくい。
