# 長期アクセスキーの発行を SCP で止める

人間は IAM Identity Center、CI は OIDC、Terraform は HCP Terraform の動的認証。
ここまで揃えたら、**IAM ユーザーのアクセスキーはもう「新しく作られたら異常」になる**。
検知して消すより、`iam:CreateAccessKey` を SCP で Deny して、作れなくするほうが早い。

## 例外の持ち方

- どうしても要るもの（例：Vault の AWS secrets engine が使う IAM ユーザー）は、SCP の Condition で特定のロールからの発行だけ許す
- 例外を SCP に書くと、「なぜ要るか」が PR に残る。Config で「キーがある」を検知して毎回 Dismiss するより説明がつく

## 先にやること

- IAM 認証情報レポートで、いま残っているキーと最終使用日を洗い出す
- 使われていないキーを消してから SCP を入れる。順番を逆にすると、ローテーションしようとした人が詰まる

## 気をつけること

- SCP は管理アカウントには効かない
- `iam:CreateAccessKey` だけ止めても、既存のキーは残る。棚卸しとセットで考える
