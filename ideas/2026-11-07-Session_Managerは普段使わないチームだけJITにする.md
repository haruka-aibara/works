# Session Manager は、普段使わないチームだけ JIT にする

Systems Manager の just-in-time node access は、普段はノードにつなげないようにしておき、申請と承認があったときだけ一時的につなげるようにする仕組み。
時間が来たら自動で閉じ、誰が何のために誰の承認で入ったかが残る。

全員に使わせると、承認が形だけになって手間が増えるだけになる。
対象は、**普段は Session Manager を使わないのに、つなげる権限だけ持っている人**に絞る。

## 分け方

- **サーバーを管理するチーム**：今まで通りいつでも入れる。`ssm:StartSession` を `ssm:resourceTag/team` で自チームのノードに絞る
- **ほかのチーム**：常時の権限を外す。必要なときは JIT で申請し、管理チームが承認する
- **委託先**：同じく JIT。保守用の VPN や RDP を置き換えれば、作業していない期間は入口が閉じている

常時権限を外すだけで、そのチームの誰かの認証情報が盗まれても Session Manager からは入れなくなる。
たまに必要になったときの抜け道が JIT。

## 管理チームには「入ったら鳴る」

管理チームまで毎回申請させる必要はない。
代わりに、本番アカウントの `StartSession` を EventBridge で拾って Slack に流す。
申請の手間なしで、心当たりのない接続に気づける。

## 本番作業を二人でやるなら

承認者を同じチームにすると、作業前にもう一人が対象と内容を確認した記録になる。
作業中までは見ていないので、画面共有やセッションログの確認で補う。
夜間の障害対応で承認者がいないときの緊急用ロールも用意しておく。

承認ポリシーの対象をタグで絞れるか、常時権限を持つ人と JIT が同じノードで共存できるか、料金は未確認。
