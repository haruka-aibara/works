# VPC フローログは、追加フィールドを入れないと本当の送信元が分からない

VPC フローログの既定のフォーマットは、ENI の目線で記録する。
NAT ゲートウェイや EKS（Pod の IP）を通った通信だと、`srcaddr` には NAT や中継の ENI のアドレスが入り、**本当の送信元・送信先が分からない**。

## 足しておくフィールド

- `pkt-srcaddr` / `pkt-dstaddr`：パケットの本当の送信元・送信先
- `pkt-src-aws-service` / `pkt-dst-aws-service`：相手が AWS のサービスか
- `flow-direction`：入りか出か
- `traffic-path`：どこを通って出たか（IGW、NAT、VPC エンドポイントなど）

## なぜ平時か

フローログのフォーマットは、あとから過去分に遡って変えられない。
侵害が分かってから足しても、**事件当時のログは既定のフォーマットのまま**。
「どの Pod から外に出たか」を調べたいときに、もう取れない。

## コスト

フィールドを足すと 1 行が長くなり、保存量は増える。
S3 に出して、Athena や DuckDB で必要なときだけ読む形なら、増えた分の負担は小さい。

各フィールドの正確な名前と、EKS で `pkt-srcaddr` に Pod の IP が入る条件は未確認。
