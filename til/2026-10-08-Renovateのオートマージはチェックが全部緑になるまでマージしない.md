# Renovate のオートマージは、チェックが全部緑になるまでマージしない

`"automerge": true` は「PR を作ったらすぐマージ」ではない。
チェックが全部成功するまで待ち、1 つでも赤ならマージせず PR を残す。
チェックが 1 つもないと、いつまでもマージされない（`ignoreTests` を入れない限り）。

## マージするのは GitHub か Renovate か

`platformAutomerge`（既定で true）は、PR に GitHub の auto-merge を仕掛ける。
GitHub が見るのはブランチ保護の必須チェックだけなので、必須チェックがないと CI を待たずにマージされうる。

リポジトリの「Allow auto-merge」が無効なら、Renovate 自身が次の実行時にマージする。
1 回の実行で 1 本ずつなので、数時間かかることがある。

## 公開からの待ち日数と組み合わせても先走らない

`minimumReleaseAge` の待ち期間中は、既定の `internalChecksFilter: "strict"` でブランチ自体が作られない。
だから GitHub の auto-merge でも、待ち期間より先にマージされることはない。

詳細とこのリポジトリでの設定は [Renovate のオートマージ](../docs/GitHub/41_Renovate/オートマージ.md)。
