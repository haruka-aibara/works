# セキュリティ機能の CI テストに AWS Emulator は今は足さなくていい

AWS Emulator は、AWS が 2026-11-11 に公開した公式のローカルエミュレータ。
Python の Lambda で作るセキュリティ機能（見つける・知らせる・直す）の CI テストに足すかを検討して、**足さないと判断した**（2026-11-15）。
CI は moto のままにする。

## 足さない理由

- できることが moto とほぼ同じ。どちらも、ハンドラを CI の Python で直接呼び、AWS 側だけを偽物に向ける
- まだ若い。v1.0.385 の時点で、公式リポジトリに未解決の「本物との差」が 6,418 件ある
- Lambda を実行する機能はあるが、中身は RustPython と互換 boto3 で、本物の Python ではない

## 「セキュリティのテストに使うな」の意味

README にこう書いてあるが、これは「ポリシーの効き目を、これで確かめるな」という意味。
認可が本物より緩いので、「拒否されるはず」を確かめるテストが通ってしまう。

甘い SG を探す、検知イベントを通知する、公開設定を閉じる、といった機能のテストには関係しない。
moto も既定では認可を一切しないので、この点で両者に差はない。

## 代わりに要るもの

エミュレータでも moto でも埋まらないのは、次の 4 つ。
壊してよい検証用の AWS アカウントを 1 つ用意して埋める。

- セキュリティ機能は、悪いことが起きた日にしか動かない。悪い状態をわざと作って発火させる
- 検知イベントを手書きすると、本物と形がずれていても気づけない。本物を採取してテストの入力にする
- 直す機能は、対象を取り違えたときの被害が大きい。実物を相手に 1 回は直させる
- 直す Lambda のロールの最小権限は、何でも通す偽物の上では分からない

## 見直すとき

moto が対応していない API に当たったら、そのテストだけ Emulator に向ける。
Bedrock の Converse が一例。

公式ドキュメントの Security のページの中身と、moto の IAM 評価がどこまで見るかは未確認。
